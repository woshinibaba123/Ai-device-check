# DeviceCheck for Mac（首版）

本机运行的 App 自动操作工具。双击「启动工具.command」，在浏览器中访问 http://127.0.0.1:8765 。关闭终端或按 Control+C 停止服务。首次被 macOS 拦截时，可右键选择打开。

## 当前能力

- 检测已连接的 Android 设备和已安装的 iOS 模拟器，显示鸿蒙环境诊断。
- 通过本机 Appium 执行 Android / iOS 的点击、输入、元素存在断言、滑动、返回及截图。
- 每一步保存截图与页面控件 XML；失败保存错误信息及可用的失败截图。
- 保存 JSON 报告，重启工具后可查看历史报告。数据位于 reports 目录。
- 采用 noReset 模式，会保留 App 数据；步骤会真实操作 App。

## 安装运行环境

工具界面仅需要 Python 3，Mac 自带版本可用。自动操作额外需要 Node.js、Appium 及平台开发环境。

```sh
npm install -g appium
appium driver install uiautomator2
appium driver install xcuitest
appium
```

Appium 需在另一个终端保持运行，默认地址 http://127.0.0.1:4723。依赖版本应符合已安装 Appium 驱动要求，可用 `appium driver doctor uiautomator2` / `appium driver doctor xcuitest` 排查。

Android：安装 Android Studio、SDK、系统镜像并创建和启动 AVD；确保 adb 在 PATH 中，或安装在 ~/Library/Android/sdk/platform-tools/adb。App 选择与模拟器 CPU 架构兼容的 APK，也可填写已安装 App 包名。

iOS：安装并完成 Xcode 初始化、安装所需 iOS runtime、创建模拟器。使用 Flutter 源码 `flutter build ios --simulator` 生成的 .app，或已安装 App 的 Bundle ID。真机 IPA 不能直接运行在模拟器。

鸿蒙：当前只检测 PATH 内的 hdc，不执行鸿蒙测试。需后续安装 DevEco Studio 并为原生鸿蒙单独实现执行适配。

## 编写步骤

Flutter 建议在源码中给关键控件提供可用于原生自动化的 Semantics 标识，并通过实际控件树确认定位。普通 Flutter Key 不保证会暴露给 Appium。

```json
[
  {"action": "wait", "seconds": 2},
  {"action": "tap", "by": "accessibility id", "value": "登录"},
  {"action": "input", "by": "accessibility id", "value": "手机号", "text": "13800000000"},
  {"action": "assert", "by": "accessibility id", "value": "验证码"},
  {"action": "swipe", "x1": 200, "y1": 600, "x2": 200, "y2": 200},
  {"action": "screenshot"}
]
```

每次选择一个设备执行，最多 200 步。不同尺寸和系统版本需先在各平台开发工具里创建对应模拟器，然后分别运行同一组步骤。

## 当前限制

这是一版可运行的基础工具，不是全部需求已经实现：不能保证遍历全部按钮或自动判定全部视觉缺陷；鸿蒙自动化尚未接入。用例模式的原生 Dio 观察范围见下文。报告中的“步骤通过”仅表示配置的操作与存在断言成功，不代表页面、接口或完整业务均正确。接入 App 源码后，可继续加入网络日志和视觉基准。

本工具只监听本机。截图、控件树、输入与错误信息可能含测试数据，请使用测试环境与测试账号。

## v0.3：按机型批量测试

在“按品牌与机型批量选择”中勾选多个型号，提供源码或 APK，选择系统策略并开始。按顺序执行，单台失败后继续；报告显示每台状态及整批计数。每个 Android 机型使用独立临时 AVD，结束后关闭并删除，仅清理工具自己创建的设备。

资料库 catalog.json 首批包含 16 款小米、Redmi、vivo、iQOO、OPPO、荣耀参考机型，每条记录包含地区、官方链接、屏幕英寸及像素、已确认的 Android 参考基线与厂商系统名称。并非全部主流机型。未知 Android 基线明确标为待核验，不用未经核实的值自动执行。系统资料为参考版本，不表示当前最新 OTA。

物理 PPI = sqrt(宽像素² + 高像素²) / 对角线英寸。默认逻辑 DPI 按物理 PPI 取整到 20 的倍数，属于可编辑的测试估算值，不是真机逻辑 DPI。不能据此保证布局与真机一致。

严格策略：仅使用本机已安装、与 Mac CPU 架构兼容、API 匹配的镜像；缺少镜像时任务失败并提示安装，不会偷换版本。可明确改选现有镜像执行屏幕参数组合测试，此时保留参考基线与实际 API 两套记录。模拟器启动后校验实际系统 API 主版本、屏幕像素和逻辑 DPI。API 次版本仅记录镜像声明，未单独验证。

还需 Android SDK Command-line Tools（avdmanager）、对应系统镜像、Java 及 Appium。可在 Android Studio 的 SDK Manager 安装。旧版 Android 在 Apple Silicon 上可能没有可用的兼容镜像，此时需换测试版本或使用真机。

重要边界：本地通用模拟器无法运行厂商专属 ROM，不模拟芯片、内存性能、刷新率、屏幕挖孔/刘海、安全区域及厂商后台策略。报告只能称为对应机型屏幕参数近似模拟测试，不是真机兼容性认证。iPhone 使用本机实际存在的 Simulator 配置，可在“本机设备 / iPhone 批量选择”多选。鸿蒙仍未接入自动执行。

验证：8 项自动检查通过（含缺镜像不替换、显式镜像保留记录、错误后继续队列），另验证本机真实 SDK 创建 AVD 参数及清理。真实 App 全流程需提供有效 App 与自动操作配置后验证。

本机补充验证：API 37.1 镜像在 120 秒启动检查中始终未就绪，已停止并清理临时设备。尚未完成真实 App 或完整模拟器会话验证。正式工具等待启动上限为 240 秒，并将超时记录为失败。

## v0.5：登录入口与自动探索

默认测试方式现在为“自动探索页面和按钮”，无需编写 JSON。选择设备，填写源码或安装包，可选启用测试账号登录，操作次数与总时长默认为 0（不限），也可自行设置上限后运行。

登录需要测试账号、密码和登录后独有的成功控件标识。默认识别普通输入框、密码输入框以及登录按钮，可展开高级定位填写 accessibility id、id 或 XPath。登录前要切换密码登录、选择地区、处理首次启动协议等，可在“登录前依次点击的按钮文字”中逐行填写精确文字；不会自动猜测或同意协议。验证码、二次验证及多步骤登录尚未自动处理。无法确认成功时不会继续探索。

凭据只用于当前批次，未加入配置文件或报告；登录阶段不截图、不保存页面结构，批次结束移除队列中的账号密码。操作日志隐藏已知凭据，保存的 XML 脱敏。Appium 日志级别调整为 warn，避免记录常规输入请求。登录后的截图可能显示账号资料，测试 App 自身也可能在设备内保留登录状态（noReset）。请使用测试环境与测试账号。

自动探索基于 Android / iOS 可访问控件树，记录页面状态指纹和点击、滚动、返回关系；尝试逐个操作有可读文字或 ID 的可点击控件，避免重复；每台操作次数与总时长默认为不限，直至当前可达控件探索完成；非零上限最多为 500 次操作、30 分钟，默认深度 6。单次驱动调用、页面加载、弹窗恢复仍有超时或重试次数。操作预算包含返回和滚动。可停止当前批次，停止会等待当前设备命令结束，后续排队目标不再执行。

默认跳过删除、支付、提交、发送、注销、同意协议等关键词，以及没有可读标识的按钮。额外关键词只会追加，不移除默认跳过项；需要此类操作时使用明确编写的自定义测试步骤。自动探索不自动生成业务表单数据，不切换到 WebView DOM，不保证识别自绘或未暴露语义的 Flutter 控件。iOS 返回需要可识别的返回控件。基于内容和布局的页面状态不等于源码路由，动态内容可能影响识别。

报告显示页面状态数、操作数、结束原因、跳转关系、跳过项和待复核操作。达到操作、时间或深度上限代表有限探索结束，不能解释为所有页面与功能通过；自动探索模式不采集完整接口链路、不自动判断全部视觉缺陷和业务正确性；用例模式可以执行显式接口断言。原来的 JSON 步骤保留在“按自定义步骤执行”模式。

验证：18 项检查通过，包含模拟登录成功确认、控件导航与返回、敏感操作跳过、预算限制、停止与登录数据脱敏。真实账号登录后的业务探索需配置有效账号和成功标识后再验证。

自动探索真实 App 验证：reports/cb4ab415ca3f/report.json。自动识别首屏、跳过协议同意项，点击 Terms of Service 并识别新页面，保存 2 个页面状态与 1 条跳转关系。本次有意限定为 1 次操作，未登录、未覆盖后续业务，也未接受协议。


## v0.6：App 内多语言批量测试

勾选“将所选机型按多种 App 语言分别测试”，源码语言列表中的 10 种语言默认全选：中文简体、English、日本語、한국어、Français、Español、Deutsch、Tiếng Việt、Italiano、中文繁體。来源为当前 Flutter 项目的 DataCache.getLanguageList；云端可能只开放其中一部分。工具源码中的 LANGUAGES 为这份列表的快照，新增语种需更新 language_tests.py。

每种语言配置：到语言列表的共同按钮路径（或逐语言覆盖）、目标选项文字、切换后的验证文字，以及可选的切换后返回路径。路径每行一个精确按钮文字。先自动登录（如果启用），再通过 App UI 切换并确认目标页面文字，然后运行探索或自定义步骤。不能使用语言选项名称本身作为验证文字。缺少语言选项或未确认标识时停止该组合，不会伪报通过。

实际执行数量 = 所选设备 × 所选语言。每个组合保存独立报告、截图、控件结构和 App 语言确认状态，按队列依次运行；一批最多 300 个组合。同一平台在会话成功后复用编译产物。Android 机型模式为每个组合创建新模拟器；已有设备和 iOS 模拟器保留 App 数据，切换路径必须适配当前 App 语言。组合的系统语言固定英语作为起始环境，目标 App 语言通过 UI 切换标识确认，不能仅依据系统语言宣称成功。

自动探索会对可见文案做启发式疑点检查：翻译键直接显示、未替换变量、替换字符（可能乱码或字体问题）。这些仅为待复核线索，不能判断翻译是否准确；长文本截断、重叠、字体缺失等仍需结合截图复核。本版不提供跨语言视觉基准比对，也不代表所有页面在全部语言均已覆盖。自定义步骤中的文字定位可能因语言变化失效，建议使用稳定的 ID。

验证：26 项自动检查通过，包含机型×语言组合展开、缺少标识时拒绝执行、真实语言选项点击后的标识验证（模拟驱动）、未开放语种停止、文案疑点提示。多语言入口及 1 设备×10 语言计数已通过界面验证。尚未使用真实账号跑完 App 的十种语言，需要先配置实际登录与语言路径及验证文字。

## 停止任务修复（2026-10-22）

停止会取消整批排队目标，并中断编译、设备启动等待和自动操作等待。工具启动的模拟器在停止后关闭；用户原先运行的模拟器不会主动关闭。已发给设备的单次操作可能仍需完成；迟到的会话创建结果会自动清理。报告保留已完成记录。

## v0.8：内置中国区登录流程

启用自动登录，默认选择内置流程，填写 Flutter 源码目录、测试账号和密码，无需再填写登录前按钮或成功页面文字。自动同意并继续、选择中国、等待数据中心自动匹配、下一步、填账号、切换密码模式、勾选协议并登录。新版 App 在空账号时禁止切换模式，因此先填账号，再等待账号类型判断。不会请求验证码。

## 多语言切换简化

语言测试不再要求或使用验证文字。按照配置路径点击目标语言选项、执行可选返回路径后直接继续测试；报告标记 switched / language_option_clicked，仅表示切换点击已执行，不代表文案或语言生效已验证。未找到目标语言控件仍停止该组合。

## 登录模式切换等待修复

输入账号后先收起 Android 键盘，等待输入及账号类型判断，再切换密码模式；等待上限 30 秒，最多两次切换。App 提示账号查询失败时记录具体原因并停止。只有密码模式得到识别后才填入密码；验证码框不会用作密码框。此修复经过模拟状态回归，真实测试账号仍需实际重跑确认。

## 账号输入确认

内置流程先输入账号并连续读回两次确认内容相符，再判断账号类型、切换账号密码登录、填密码和登录。账号内容未确认时不切换模式。读回内容只在内存中比较，不加入日志或报告。

## PDF 机型报告与探索恢复

每个机型 / 语言任务结束后生成 report.pdf，界面提供“下载本机型 PDF 报告”。PDF 包含设备、环境、结束原因、操作路径、未覆盖项、异常、日志和页面截图。既有报告也可通过下载入口生成 PDF。本机设备只记录设备编号时不会补猜品牌机型。

PDF 依赖隔离环境：`/usr/bin/python3 -m venv .runtime/pdf-venv`，然后 `.runtime/pdf-venv/bin/pip install 'reportlab==4.4.10'`。中文字体使用 macOS Arial Unicode。

截图按页面状态去重，登录和密码页不截图。页面识别仍基于可访问控件树，不等于源码路由；滚动、弹窗或动态文案可能形成不同状态。返回后页面状态变化时记录待复核项并继续探索，App 边界、密码页、时间与次数限制仍生效。业务全流程应使用明确步骤及成功断言，探索结束不表示所有业务验证通过。

## 源码引导的页面探索

当前 App 的源码探索会读取 Routers 常量、GetPage、Get.toNamed 等调用及本地语言资源，形成静态页面 / 入口候选清单，优先探索源码中的底部导航和命名入口。仅对独立测试副本添加 NavigatorObserver，读取白名单中的实际路由名称，不读取路由参数。每个路由（主页区分选中的底部标签）保留一张截图；路由不可用时按 UI 状态去重。报告列出源码路由数、实际观察到的路由和未覆盖路由。角色权限、数据依赖、硬件连接、无语义图标和 WebView 内部页面仍可能阻碍覆盖；静态近邻文案匹配只是候选，不能当作已完成跳转。

点击、滚动和返回后等待页面稳定，加载层不作为无控件页面截图。尚需真实账号重新执行，才能确认当前版本的 App 页面覆盖范围。

## 页面弹窗自动关闭

探索页面前优先识别“关闭、取消、稍后、跳过、知道了”等文字，或明确的 close / cancel 控件标识，关闭后再记录页面截图。支持常见中文、英文、日文等标签和系统权限拒绝按钮。关闭操作计入操作次数和时间预算，写入 JSON / PDF 弹窗处理记录。相同弹窗连续两次关闭仍未消失，或原生弹窗没有明确关闭控件时，记录 popup_blocked，避免继续点击背景。通用弹窗关闭不会将“支付、同意、允许、确定、下一步”当作关闭按钮。没有文字或控件标识的自绘关闭图标仍需补充可访问性标识。

## Flutter 构建入口与环境

网页可填写 Flutter 启动入口，本项目默认 lib/main_eng.dart。构建明确传入 -t 参数，报告记录 build_entrypoint。main.dart 初始化 pro，main_eng.dart 初始化 eng；缓存测试包入口不符会拒绝复用。自动化使用 debug 包以读取脱敏的登录和路由结果，不等同于 release 验收。

页面探索会按路由、WebView 标题、选中页签共享已测控件和滚动预算；截图仍区分各页面内容状态。H5 返回优先使用页面的返回图标，系统返回被拦截时保留返回路径，必要时重新打开 App 恢复。卡住的加载页保留诊断截图。弹窗关闭失败会尝试返回其他入口，仍无法恢复时明确记录未完成。

## CodeBuddy AI 大纲测试

在「配置测试」工作区中设置 CodeBuddy CLI 访问密钥、账号站点和模型，再选择「AI 大纲测试」。模型列表来自当前 CLI 的支持列表及本机模型 ID 配置，不代表账号已开通或免费；也可以填写自定义模型 ID。用「测试所选模型」确认认证、额度和模型权限。

本项目优先使用独立安装的 CLI，不改变全局安装：

```sh
npm install --prefix .runtime/codebuddy @tencent-ai/codebuddy-code@2.179.2 --registry=https://registry.npmjs.org
```

勾选“记住 AI 密钥”后，访问密钥保存在 macOS 登录钥匙串中，重启工具后自动使用；取消勾选并保存则仅用于本次会话。界面不回显密钥，也不将密钥写入浏览器存储、报告或项目配置。也支持启动服务时已配置的 `CODEBUDDY_API_KEY` 环境变量。“忘记已保存密钥”会删除钥匙串条目并清除本次密钥，不修改启动环境中的密钥。若 macOS 要求访问钥匙串，请按系统提示授权。站点和模型偏好保存在浏览器本地。

测试账号在勾选“记住测试账号”时自动保存在当前浏览器，下次打开自动填写；可取消勾选或点击“忘记账号”清除。测试密码仍不保存。

输入大纲时提供准确的按钮文字、前置条件、测试数据和可验证的预期结果。可选发送 Flutter 源码结构摘要（不发送整棵源码树），默认不发送。连接检查和生成均调用 CodeBuddy 服务并使用账号额度；不要在大纲中填写密码或其他凭据。

生成后可展开用例查看步骤，或编辑 JSON 后刷新预览。服务端在开始测试前重新校验全部计划，必须包含明确断言；缺少信息的用例保持「待补充」，不会猜测操作或算作通过。全部待补充时不能开始测试。AI 规划最多 30 条用例、每条最多 80 步，请求超时为 180 秒。

执行沿用现有用例引擎、自动登录、多语言和设备队列，每条用例前会尝试恢复并点击「首页」，因此当前适配包含该导航的 App。AI 不直接操作电脑，也不在执行中自行重新规划。结果保留逐步截图、用例状态和原因；报告页可下载 AI 计划、JSON 和 PDF。AI 大纲模式不生成 Excel，原 Excel 模式仍可回填工作簿。

CodeBuddy 仅接收文本规划请求：使用临时配置目录，禁用工具、MCP 和会话持久化，不允许模型读取文件或执行命令。实际保存操作仍必须绑定接口断言，删除、支付、凭据修改等操作继续受现有执行器限制。

生成大纲时，界面显示实际处理阶段（准备大纲、读取源码摘要、检查认证、等待模型、提取响应、校验计划）以及总耗时和当前阶段耗时。已完成阶段保留记录；模型内部的推理进度和完成百分比不可获取。刷新同一标签页后可重新连接尚未结束的生成任务，服务重启则需重新生成。模型响应阶段的超时上限为 180 秒，不包含此前的源码分析时间。

### H5 源码目录

在「应用来源」中填写独立的 H5 本机项目根目录（包含 package.json 或 index.html），目录会保存在当前浏览器供下次使用。当前不接受线上网页或 Git 仓库 URL，请先把代码下载到本机。在 AI 大纲测试中勾选“附带上方 Flutter / H5 项目的源码信息”，即可结合 Flutter 入口和 H5 相关页面片段规划用例，也可仅填写 H5 目录。

H5 分析只读取受限数量的页面源码，不执行项目代码，不读取 .env、依赖、构建目录及常见凭据配置文件。相关片段将发送到 CodeBuddy。此配置提供规划证据，不增加 WebView DOM 操作能力，无法由现有执行器可靠操作的 H5 步骤仍需适配。

### 业务计划与自动化适配

AI 大纲规划分为两次独立模型请求：先按测试工程师的方式生成完整业务用例，每步包含操作和预期；再将每步匹配到现有执行器。点击“生成业务用例”仅请求业务计划；随后可按需点击“匹配自动化步骤”，独立请求适配，避免查看业务计划也必须等待第二轮模型响应。每次模型请求最多等待 180 秒，整个流程可能超过 180 秒。

源码定位不全、测试数据不足或 H5 执行能力未接入，只影响对应步骤的自动化适配，不删除业务步骤。界面区分“业务计划已生成”“自动化候选”和完整可交给执行器的用例。单步候选不作为独立通过或可执行用例，只有整条操作与结果断言完整并通过校验后才能执行；自动化匹配失败时仍保留业务计划。原有格式的已编辑计划继续兼容。

## Excel 按语言接力生成与测试

在 Excel 测试区读取用例，启用多语言并配置切换路径及语言选项，点击“按语言生成并自动接力测试”。工作表使用语言名称（例如 `01_中文简体`、`02_English`），按 Excel 工作表顺序处理；等级筛选继续生效。

每种语言单独保存 AI 计划，存在可执行步骤才加入设备队列。第一种语言测试时，后台可以继续生成下一种语言，设备测试串行执行，接力批次保留前面报告。没有完整步骤的用例仍记录待转换，不当作产品断言失败。Flutter/H5 索引在同一轮跨语言复用，文案和定位仍按各语言分别匹配。

“停止语言接力”停止后续生成和排队，并请求停止当前测试；正在等待的 AI 请求会在返回或超时后停止。关闭网页不影响后台运行，刷新后可查看接力状态；关闭服务会中断接力。接力状态保存在 `.runtime/language-pipelines/`，不记录测试账号密码。

## 自定义步骤的 H5 执行

自定义模式支持 `wait_for`（使用原生定位方式，timeout 为 1～60 秒），以及
`web_tap`、`web_input`、`web_assert`、`web_assert_input`、`web_back`、`web_save`。
H5 步骤使用 `by: text/css/xpath`；每步进入被测 App 的唯一 WebView，结束后切回原生上下文。
H5 需要可调试的 WebView 和匹配的驱动。`web_save` 必须绑定实际写接口的 method、path、成功码及可选响应字段断言；
提交只点击一次，结果不确定时停止，不自动重提。证据保存在报告的 custom_step_results 中。
自动登录仍通过界面中的自动登录配置完成，不把账号密码写进步骤。

报修全流程尚未实测通过；账号类型会决定入口是 repairForm 还是 repairList，
必须确认实际 DOM、表单必填项、有效测试机器人和提交接口之后才能固定完整步骤。

## 中文业务步骤（首版）

在“按自定义步骤执行”中选择“中文业务步骤”，每行写一个操作，然后点击“预览识别结果”。
支持“点击底部我的”“确认消息页面打开”“联系人填写「张三」”“门店选择「门店名」”
“机器人选择第一台”“等待报修表单加载完成”“勾选用户协议”“点击提交，检查是否提交成功”等固定句式。
复杂或未识别的句子会在启动前显示行号，不会忽略。原 JSON 步骤保留在高级模式。

运行时从原生控件树或 H5 DOM 查找目标；源码翻译键将中文业务名称映射到各语言文案，
字段填写后回读原文；多个同名控件会停止。Flutter 翻译从 assets/i18n/*.json 读取，
H5 从所填源码目录的 src/lang、src/locales、src/i18n 读取，不执行项目脚本。
无翻译映射时仅有内置常用词，不保证识别任意语言或任意自然语言句式。
首页、消息、我的的页面检查和报修协议/提交目前是当前 Keenon App 的适配；
报修提交绑定 POST /api/devops/aftersale/work/order，必须收到业务码610000。
未知页面提交不执行；没有候选项会明确报业务字段名称，不伪报通过。
这一版尚未完成中文步骤驱动真实报修提交的端到端实测。

多语言运行后的中文导航会识别当前语言/通用设置页，最多点击三次页面返回按钮，
找到目标底部页签后再切换；不会在桌面、WebView、密码页或未知页面盲目返回。
这用于修复切换语言后停在设置页、后续“回到首页”找不到页签的问题。
