# DeviceCheck for Mac（首版）

V2 首批修复已接入：已安装应用、原始安装包、源码测试构建三种运行方式；旧包页面登录验证、工具侧逻辑定位、命令耗时和历史报告保留。使用方法及当前验证范围见 [V2首版使用说明](V2首版使用说明.md)。未完成目标旧包的实机基线，候选定位规则需按实际版本验证。

源码匹配会识别登录自定义输入框和页面字段辅助组件，跟踪页面相对导入的控制器与仓库，并按控件及其回调关联导航文字，避免借用相邻按钮的标签。AI 摘要保留目标页面入口、接口和业务成功码，H5 页面优先附带其导入的接口文件。APN 局域网操作单独标为需设备适配，不当作普通 HTTP 保存。此次证据提取升级会使旧匹配缓存失效；重新生成后，候选步骤仍须设备验证。

登录匹配统一使用 `home/login_config/login` 起点；首条登录配置路由断言会校正登录前起点。仅打开选择框、未选择指定国家或核对语言，以及用进入登录页替代完成登录等已知缺项，会保留为部分匹配，不计完整候选。登录凭据脱敏占位使用 `input_local` 本机引用，不发明明文，也不单凭占位判定凭据未配置。混合用例摘要优先保留登录前配置、登录、通用设置和语言页；生成进度显示实际发送的页面、输入框、接口数量及 H5 文件名，便于核对证据。此校验只能识别已知漏项，不代替设备业务验证。

Excel 自动化适配在收集摘要前先拆分业务用例，再复用本轮源码索引为每个小批筛选证据。小批源码摘要超限会自动退回逐条处理；单条仍超限时仅该条标记工具处理失败，其余结果和增量进度保留。摘要大小、事件流和传输超限等工具错误不会保存为业务受阻缓存，旧缓存中的同类错误也会被忽略。

## AI 自主操作（试用）

在“测试方式”选择“AI 自主操作 · 实时页面”，填写一句测试目标（页面文字检查点可选），并勾选允许发送脱敏页面文字，然后点击“开始 AI 自主操作”。设备、源码/安装包、账号和语言仍使用上方配置；自动登录由原有专用流程完成。

例如目标填写“进入消息页，再进入我的页查看通用设置，最后返回首页”；检查点每行填写一个对应语言的实际页面文字。检查点只证明文字曾经出现，不代表整个业务结果正确。

执行器每轮读取当前原生控件及 H5 DOM，将脱敏文字交给 CodeBuddy 决定一个动作，重新确认页面没变化后执行。支持点击、返回、向下滚动、使用本地指定数据输入和控件存在检查。模型不能执行脚本、任意 XPath、坐标、命令或接口请求。页面变化会丢弃旧决策，连续重复操作会停止。默认最多 30 轮、600 秒，最多允许 100 轮、1800 秒；不包括构建和自动登录时间。普通停止按钮也会中断正在等待的本轮 AI 请求。

截图保存在本机，当前版本不将图片发送给模型，因此不能仅凭视觉识别无文字图标或验证布局。输入内容不发送给模型；模型只能选择已配置数据的字段名称。密码页面、外部 App、驱动不可用或不确定操作结果都会停止，不会改用盲点坐标。常见提交、删除、支付、保存、账号及设备任务按钮会拦截；任意 App 的多语言业务语义不能仅靠关键词完全识别，请在测试环境试用，真实写操作继续使用已有专用流程。

每轮调用会使用 CodeBuddy 账号额度。结果显示“待复核”，不会因为模型返回完成就判定业务通过。每个任务的 `ai-operator.json` 保存实际操作、控件标签和文字检查点；任务界面提供报告入口。

本版已通过自主循环、API、取消、既有 AI 与 H5 的 98 项回归，以及独立 Chrome 页面入口验证。尚未完成真实 App 的自主操作验证；当前开发机没有连接 Android 设备。

本机运行的 App 自动操作工具。双击「启动工具.command」，在浏览器中访问 http://127.0.0.1:8765 。关闭终端或按 Control+C 停止服务。首次被 macOS 拦截时，可右键选择打开。

## 当前能力

- 检测已连接的 Android 设备和已安装的 iOS 模拟器，显示鸿蒙环境诊断。
- 通过本机 Appium 执行 Android / iOS 的点击、输入、元素存在断言、滑动、返回及截图。
- 每一步保存截图与页面控件 XML；失败保存错误信息及可用的失败截图。
- 保存 JSON 报告，重启工具后可查看历史报告。数据位于 reports 目录。
- 采用 noReset 模式，会保留 App 数据；步骤会真实操作 App。

## 安装运行环境

工具界面仅需要 Python 3，Mac 自带版本可用。自动操作额外需要 Node.js、Appium 及平台开发环境。

```sh
npm install -g appium
appium driver install uiautomator2
appium driver install xcuitest
appium
```

Appium 需在另一个终端保持运行，默认地址 http://127.0.0.1:4723。依赖版本应符合已安装 Appium 驱动要求，可用 `appium driver doctor uiautomator2` / `appium driver doctor xcuitest` 排查。

Android：安装 Android Studio、SDK、系统镜像并创建和启动 AVD；确保 adb 在 PATH 中，或安装在 ~/Library/Android/sdk/platform-tools/adb。App 选择与模拟器 CPU 架构兼容的 APK，也可填写已安装 App 包名。

iOS：安装并完成 Xcode 初始化、安装所需 iOS runtime、创建模拟器。使用 Flutter 源码 `flutter build ios --simulator` 生成的 .app，或已安装 App 的 Bundle ID。真机 IPA 不能直接运行在模拟器。

鸿蒙：当前只检测 PATH 内的 hdc，不执行鸿蒙测试。需后续安装 DevEco Studio 并为原生鸿蒙单独实现执行适配。

## 编写步骤

Flutter 建议在源码中给关键控件提供可用于原生自动化的 Semantics 标识，并通过实际控件树确认定位。普通 Flutter Key 不保证会暴露给 Appium。

```json
[
  {"action": "wait", "seconds": 2},
  {"action": "tap", "by": "accessibility id", "value": "登录"},
  {"action": "input", "by": "accessibility id", "value": "手机号", "text": "13800000000"},
  {"action": "assert", "by": "accessibility id", "value": "验证码"},
  {"action": "swipe", "x1": 200, "y1": 600, "x2": 200, "y2": 200},
  {"action": "screenshot"}
]
```

每次选择一个设备执行，最多 200 步。不同尺寸和系统版本需先在各平台开发工具里创建对应模拟器，然后分别运行同一组步骤。

## 当前限制

这是一版可运行的基础工具，不是全部需求已经实现：不能保证遍历全部按钮或自动判定全部视觉缺陷；鸿蒙自动化尚未接入。用例模式的原生 Dio 观察范围见下文。报告中的“步骤通过”仅表示配置的操作与存在断言成功，不代表页面、接口或完整业务均正确。接入 App 源码后，可继续加入网络日志和视觉基准。

本工具只监听本机。截图、控件树、输入与错误信息可能含测试数据，请使用测试环境与测试账号。

## v0.3：按机型批量测试

在“按品牌与机型批量选择”中勾选多个型号，提供源码或 APK，选择系统策略并开始。按顺序执行，单台失败后继续；报告显示每台状态及整批计数。每个 Android 机型使用独立临时 AVD，结束后关闭并删除，仅清理工具自己创建的设备。

资料库 catalog.json 首批包含 16 款小米、Redmi、vivo、iQOO、OPPO、荣耀参考机型，每条记录包含地区、官方链接、屏幕英寸及像素、已确认的 Android 参考基线与厂商系统名称。并非全部主流机型。未知 Android 基线明确标为待核验，不用未经核实的值自动执行。系统资料为参考版本，不表示当前最新 OTA。

物理 PPI = sqrt(宽像素² + 高像素²) / 对角线英寸。默认逻辑 DPI 按物理 PPI 取整到 20 的倍数，属于可编辑的测试估算值，不是真机逻辑 DPI。不能据此保证布局与真机一致。

严格策略：仅使用本机已安装、与 Mac CPU 架构兼容、API 匹配的镜像；缺少镜像时任务失败并提示安装，不会偷换版本。可明确改选现有镜像执行屏幕参数组合测试，此时保留参考基线与实际 API 两套记录。模拟器启动后校验实际系统 API 主版本、屏幕像素和逻辑 DPI。API 次版本仅记录镜像声明，未单独验证。

还需 Android SDK Command-line Tools（avdmanager）、对应系统镜像、Java 及 Appium。可在 Android Studio 的 SDK Manager 安装。旧版 Android 在 Apple Silicon 上可能没有可用的兼容镜像，此时需换测试版本或使用真机。

重要边界：本地通用模拟器无法运行厂商专属 ROM，不模拟芯片、内存性能、刷新率、屏幕挖孔/刘海、安全区域及厂商后台策略。报告只能称为对应机型屏幕参数近似模拟测试，不是真机兼容性认证。iPhone 使用本机实际存在的 Simulator 配置，可在“本机设备 / iPhone 批量选择”多选。鸿蒙仍未接入自动执行。

验证：8 项自动检查通过（含缺镜像不替换、显式镜像保留记录、错误后继续队列），另验证本机真实 SDK 创建 AVD 参数及清理。真实 App 全流程需提供有效 App 与自动操作配置后验证。

本机补充验证：API 37.1 镜像在 120 秒启动检查中始终未就绪，已停止并清理临时设备。尚未完成真实 App 或完整模拟器会话验证。正式工具等待启动上限为 240 秒，并将超时记录为失败。

## v0.5：登录入口与自动探索

默认测试方式现在为“自动探索页面和按钮”，无需编写 JSON。选择设备，填写源码或安装包，可选启用测试账号登录，操作次数与总时长默认为 0（不限），也可自行设置上限后运行。

登录需要测试账号、密码和登录后独有的成功控件标识。默认识别普通输入框、密码输入框以及登录按钮，可展开高级定位填写 accessibility id、id 或 XPath。登录前要切换密码登录、选择地区、处理首次启动协议等，可在“登录前依次点击的按钮文字”中逐行填写精确文字；不会自动猜测或同意协议。验证码、二次验证及多步骤登录尚未自动处理。无法确认成功时不会继续探索。

凭据只用于当前批次，未加入配置文件或报告；登录阶段不截图、不保存页面结构，批次结束移除队列中的账号密码。操作日志隐藏已知凭据，保存的 XML 脱敏。Appium 日志级别调整为 warn，避免记录常规输入请求。登录后的截图可能显示账号资料，测试 App 自身也可能在设备内保留登录状态（noReset）。请使用测试环境与测试账号。

自动探索基于 Android / iOS 可访问控件树，记录页面状态指纹和点击、滚动、返回关系；尝试逐个操作有可读文字或 ID 的可点击控件，避免重复；每台操作次数与总时长默认为不限，直至当前可达控件探索完成；非零上限最多为 500 次操作、30 分钟，默认深度 6。单次驱动调用、页面加载、弹窗恢复仍有超时或重试次数。操作预算包含返回和滚动。可停止当前批次，停止会等待当前设备命令结束，后续排队目标不再执行。

默认跳过删除、支付、提交、发送、注销、同意协议等关键词，以及没有可读标识的按钮。额外关键词只会追加，不移除默认跳过项；需要此类操作时使用明确编写的自定义测试步骤。自动探索不自动生成业务表单数据，不切换到 WebView DOM，不保证识别自绘或未暴露语义的 Flutter 控件。iOS 返回需要可识别的返回控件。基于内容和布局的页面状态不等于源码路由，动态内容可能影响识别。

报告显示页面状态数、操作数、结束原因、跳转关系、跳过项和待复核操作。达到操作、时间或深度上限代表有限探索结束，不能解释为所有页面与功能通过；自动探索模式不采集完整接口链路、不自动判断全部视觉缺陷和业务正确性；用例模式可以执行显式接口断言。原来的 JSON 步骤保留在“按自定义步骤执行”模式。

验证：18 项检查通过，包含模拟登录成功确认、控件导航与返回、敏感操作跳过、预算限制、停止与登录数据脱敏。真实账号登录后的业务探索需配置有效账号和成功标识后再验证。

自动探索真实 App 验证：reports/cb4ab415ca3f/report.json。自动识别首屏、跳过协议同意项，点击 Terms of Service 并识别新页面，保存 2 个页面状态与 1 条跳转关系。本次有意限定为 1 次操作，未登录、未覆盖后续业务，也未接受协议。


## v0.6：App 内多语言批量测试

勾选“将所选机型按多种 App 语言分别测试”，源码语言列表中的 10 种语言默认全选：中文简体、English、日本語、한국어、Français、Español、Deutsch、Tiếng Việt、Italiano、中文繁體。来源为当前 Flutter 项目的 DataCache.getLanguageList；云端可能只开放其中一部分。工具源码中的 LANGUAGES 为这份列表的快照，新增语种需更新 language_tests.py。

每种语言配置：到语言列表的共同按钮路径（或逐语言覆盖）、目标选项文字、切换后的验证文字，以及可选的切换后返回路径。路径每行一个精确按钮文字。先自动登录（如果启用），再通过 App UI 切换并确认目标页面文字，然后运行探索或自定义步骤。不能使用语言选项名称本身作为验证文字。缺少语言选项或未确认标识时停止该组合，不会伪报通过。

实际执行数量 = 所选设备 × 所选语言。每个组合保存独立报告、截图、控件结构和 App 语言确认状态，按队列依次运行；一批最多 300 个组合。同一平台在会话成功后复用编译产物。Android 机型模式为每个组合创建新模拟器；已有设备和 iOS 模拟器保留 App 数据，切换路径必须适配当前 App 语言。组合的系统语言固定英语作为起始环境，目标 App 语言通过 UI 切换标识确认，不能仅依据系统语言宣称成功。

自动探索会对可见文案做启发式疑点检查：翻译键直接显示、未替换变量、替换字符（可能乱码或字体问题）。这些仅为待复核线索，不能判断翻译是否准确；长文本截断、重叠、字体缺失等仍需结合截图复核。本版不提供跨语言视觉基准比对，也不代表所有页面在全部语言均已覆盖。自定义步骤中的文字定位可能因语言变化失效，建议使用稳定的 ID。

验证：26 项自动检查通过，包含机型×语言组合展开、缺少标识时拒绝执行、真实语言选项点击后的标识验证（模拟驱动）、未开放语种停止、文案疑点提示。多语言入口及 1 设备×10 语言计数已通过界面验证。尚未使用真实账号跑完 App 的十种语言，需要先配置实际登录与语言路径及验证文字。

### H5 源码目录

### 业务计划与自动化适配

AI 大纲规划分为两次独立模型请求：先按测试工程师的方式生成完整业务用例，每步包含操作和预期；再将每步匹配到现有执行器。点击“生成业务用例”仅请求业务计划；随后可按需点击“匹配自动化步骤”，独立请求适配，避免查看业务计划也必须等待第二轮模型响应。每次模型请求最多等待 180 秒，整个流程可能超过 180 秒。

源码定位不全、测试数据不足或 H5 执行能力未接入，只影响对应步骤的自动化适配，不删除业务步骤。界面区分“业务计划已生成”“自动化候选”和完整可交给执行器的用例。单步候选不作为独立通过或可执行用例，只有整条操作与结果断言完整并通过校验后才能执行；自动化匹配失败时仍保留业务计划。原有格式的已编辑计划继续兼容。

AI 自主操作的检查点可留空：模型声明完成后，会另行核对目标、操作历史与当前页面，并校验引用文字确实存在。该结果仍是 AI 辅助核对，不等同于后台业务已通过确定性验证。

自主操作默认开启“快速执行”：对进入首页/消息/我的/通用设置及切换支持语言的简单中文目标，优先逐页匹配本地路径。不识别的目标或找不到控件时交给 AI。AI 也可一次返回最多 6 步点击/断言建议，每步在当前真实页面重新唯一匹配；匹配不上会丢弃剩余建议。未填检查点时仍保留最后的 AI 结果核对。报告用 origin 区分本地路径和 AI 决策，model_calls 记录实际模型调用次数。

## 简化配置页

“配置测试流程”默认显示一句话目标和开始按钮。应用路径、启动入口和登录选项在同一浏览器自动记住；无已存配置时，从现有本地运行配置恢复非密字段。密码仍从本机凭据库读取，不写入简化配置或浏览器存储。检查点、输入数据、超时和轮数收进补充选项；AI、Excel、自定义步骤、多语言和登录设置仍可在“应用、账号及其他测试设置”中修改。页面更新不需要停止当前测试。

## Excel 生成提速

点击“快速生成运行步骤”时，默认优先用现有严格语法本地适配常见步骤，再复用完整候选缓存，仅将剩余用例交给 AI。同一语言范围内的相同业务只适配一次，但仍保留每个 Excel 原行的独立执行和结果。不同语言工作表不盲目去重；语言接力的原生步骤只在源码翻译键能唯一确认时跨语言复用。H5、凭据和不完整计划不作跨语言复用。相同语言的登录计划可缓存 input_local 本机凭据引用，实际账号密码仍在执行时读取，不保存凭据值。

缓存位于 `.runtime/excel-ai-plans/reusable`，保存的是待执行候选步骤，不是 pass 结果。用例内容、预期、语言条件、源码内容或验收口径变化会使对应缓存失效。切换生成模型不再使已生成的完整计划失效；兼容读取当前模型此前保存的旧格式缓存，命中后迁移到与模型无关的缓存。当前源码失效策略是相关目录全量内容指纹，优先保证不复用旧步骤。较短的复杂用例可两条合批请求，超时会回退到逐条。页面和计划 JSON 的 generation_stats 会区分本地匹配、缓存、重复复用、跨语言复用及交给 AI 的条数。

## 本地操作知识库

AI 自主操作默认开启自动学习。每次导航后保存页面指纹、已脱敏的目标控件标签和结果页面指纹；目标核对完成后才启用规则。下次遇到同一 App 版本、相同目标、页面和流程位置，优先复用知识库。仍在当前页面唯一定位控件，不复用旧坐标或设备元素 ID。返回页面与历史不同会停用该规则并重新决策，不盲目重复点击。

完成证据也可在当前页面重新核对后复用，无需每次重新请求 AI；该结果仍为待复核，不直接等于业务 pass。页面显示已记录和可复用数量，每次任务报告区分知识库命中数、AI调用数和失配数。

数据在 `.runtime/action-knowledge/navigation.sqlite3`，采用本地 SQLite 保存，不保存目标全文、整页控件树、截图或输入内容。输入、提交、删除、支付和设备任务不自动学习重放。配有本地输入数据、目标含需脱敏内容或无法确认源码/安装包版本时不启用重放。可在补充选项关闭自动学习。

这一版记录的是工具执行的 AI 自主操作，暂不录制用户在模拟器中的手动点击，也不从旧截图猜测导入未验证规则。模拟页面回归中，一个两步导航流程首次调用 AI 4 次，学习后第二次为 0 次；这不是真实 App 的速度基准。

### Excel 增量保存与受阻复用

每个 AI 小批结果返回后立即校验并落盘，不再等整份 Excel 结束。中断时，已处理的候选可在再次生成时命中缓存；未返回的那次 AI 请求不能续传。进度快照保存在 `.runtime/excel-ai-plans/in-progress`，完成后转为原有完整计划。

明确的缺数据、未支持控件等受阻原因会缓存 30 天（旧记录沿用原到期时间），避免反复请求模型得到相同说明。超时、连接失败和无效返回不作这种缓存。修改用例数据或源码会重新适配；也可点击“重新分析受阻项”主动重试。受阻复用不表示已有可执行步骤或测试通过。

### 导航操作的同义表达

页面操作知识库和 Excel 适配缓存支持本地导航意图归一化：例如“进入通用设置”“打开通用设置页面”“跳转到通用设置”可匹配同一操作，无需仅为换个动词请求 AI。支持明确的起点/终点和导航顺序；数据、语言、前置条件、非导航结果要求仍保持区分。不使用字符串相似度强行选最接近的规则；未能完整理解、附带删除/提交或命中冲突历史时保留原意交给 AI。

对旧知识库及旧 Excel 缓存会尝试有上限的常见说法兼容匹配，所有其他条件仍需一致。没有可确认的旧规则时，首次仍需要适配并学习；不保证任意自然语言改写都能自动匹配。

完整历史计划在源码索引分析前匹配，全部命中时跳过源码索引。生成开始显示历史完整计划命中数量；每批请求 AI 前显示已处理条数及本批缺少可复用完整计划的数量。未命中仍可能由源码、语言、验收条件变化、历史计划不完整或凭据值不可缓存造成，目前不逐项追溯旧缓存的失效原因。

Excel 生成和 AI 计划页面增加“AI 调用实况”，显示最近 20 次请求的模型、站点、请求字符数、等待/接收/完成/失败状态，以及最近 12,000 字符的脱敏回复。CodeBuddy 使用 stream-json 与 include-partial-messages 接收实际文本增量；页面通过原有进度轮询刷新。仅展示回复文本，不展示 thinking、工具事件、原始 stderr 或请求凭据。没有收到服务端文本时显示等待首段回复；本机不能保证上游一定逐字返回。实况仅保存在服务内存，重启后清空。

## 模块脚本快速执行（首版）

选择“自定义步骤”，展开“模块脚本库 · 新增 JSON / 手动确认入库”。填写名称和 JSON，点击“使用此 JSON 试运行”，再点击原有开始测试按钮。试运行不存入脚本库。运行结束后点击“刷新脚本及成功记录”，选择本 JSON 的完整成功记录，检查结果并勾选“手动确认此 JSON 运行稳定”，再点击“确认稳定并存入脚本库”。下次可选择已确认脚本运行。参数仅用于本次运行，不写入模块文件；请勿把账号密码放入名称或定位文案。脚本文件保存在 `.runtime/module-scripts`，相同内容复用相同版本标识，修改内容生成新版本。

首版支持原生 `tap`、`input`、`assert`、`back`，定位支持 `accessibility id`、`id`、Android UIAutomator 和 iOS predicate；最后一步必须为 `assert`。`timeout` 为等待控件可见（操作还须启用）的最长轮询预算，单位秒，默认 8，最大 60；单次驱动命令仍受原有通信超时约束。控件未出现时每 0.2 秒重查；多个匹配或通信异常直接失败，写操作不自动重试。每一步重新获取元素，不保存坐标及元素 ID。

输入步骤使用 `{"action":"input","by":"accessibility id","value":"search","parameter":"store_code"}`，本次参数填写 `{"store_code":"S001"}`。输入先清空字段。其他步骤的 `value` 目前为固定定位表达式，不支持参数模板。示例控件标识必须替换为实际页面标识。

模块执行直接调用驱动，不调用 AI，不逐步读取整页或截图；失败沿用现有截图权限和诊断流程。报告的 `module_script` 保存模块版本，`custom_step_results` 保存各步耗时及结果。最后的存在/可见断言仅证明对应控件出现，不等于接口或完整业务通过。运行前请准备起点页面，检查自动登录和语言准备配置。

脚本入库需要手动确认及服务器落盘的成功报告；失败、停止、待复核、未结束、步骤不完整或 JSON 不一致均不能入库。修改 JSON 后需重新试运行并确认。库文件保留确认时间与运行报告编号；原有未确认文件不会列入可运行脚本库。一次通过不自动代表稳定，稳定性由你根据实际运行结果手动判断。尚未接入版本兼容检查、连续运行成功率面板及 H5 模块；请按 App 版本、平台和语言分别实测。

模块执行器验证：`python3 -m unittest test_module_scripts test_manual_steps test_v2_profile test_cancellation -q`。测试兼容 pytest，可在已安装 pytest 的环境中使用 `python3 -m pytest -q test_module_scripts.py`；pytest 不参与生产点击循环。
